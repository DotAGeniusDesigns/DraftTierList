# DraftList

Fantasy football draft board and toolkit. Create React App + Tailwind on the
front end, Vercel Functions + Neon Postgres behind `/api`. Accounts are optional
by design — everything works from `localStorage` without signing in, and cloud
sync is additive.

## Commands

```bash
npm start            # dev server
npm run build        # production build (CI=true treats warnings as errors)
npm test             # react-scripts test

npm run injuries     # refresh src/utils/injuryReport.js from ESPN
npm run offseason    # refresh src/utils/offseasonNews.js from ESPN
npm run stats        # refresh src/utils/playerStats.js from Sleeper + nflverse
```

## Generated modules — never hand-edit

Several files in `src/utils/` are build artifacts with a generator named in their
first line. Editing them by hand is silently undone on the next refresh.

| File | Generated by |
|---|---|
| `playerDatabase.js` | `scripts/generatePlayerDatabase.js` (from `scripts/rawTierList2026.txt`) |
| `injuryReport.js` | `scripts/updateInjuries.js` |
| `offseasonNews.js` | `scripts/updateOffseason.js` |
| `playerStats.js` | `scripts/updateStats.js` |
| `projectionModel.js` | `scripts/analysis/fit_wide.py` |

Each generator fetches a public feed, compares against what is committed, and
only rewrites when something actually changed. All support `--dry-run` and
`--verbose`. Raw feed downloads are cached under `.cache/nflstats/` (gitignored);
pass `--refresh` to bypass.

`playerDatabase.js` is the roster source of truth — 399 players keyed by a slug
id. Anything reading a persisted id must run it through `migratePlayerId` first
(see `playerData.js`), or renamed players silently vanish from saved boards.

## Draft Kit

`/draft-kit` — a 2026 projection card for the top 150 players by consensus rank.
Tagged **beta** via `beta: true` on its entry in `routes.js`; the navbar and the
page header both read that one flag.
Route is lazy-loaded in `App.jsx`, and must stay that way: `playerStats.js` is
~720KB and would otherwise more than double the main bundle for every visitor.

### The pieces

- `src/utils/playerStats.js` — per-player season history, 2009–2025. Fantasy
  points pre-scored by Sleeper in all three formats, plus opportunity stats
  (targets, red-zone looks, snaps) and nflverse market share (`adv`). Also carries
  `age` and, for players with no NFL snaps, `draft` capital.
- `src/utils/projectionModel.js` — fitted coefficients.
- `src/utils/draftScore.js` — runtime scoring: projection, projected games,
  season total, positional rank, value over replacement, value vs ADP.
- `src/components/DraftKit.jsx` — the page and its methodology modal.
- `scripts/analysis/` — the research and the fitting scripts. See its README.

### What the model does

Predicts **half-PPR points per game** for the coming season. Fitted on 3,136
year-over-year transitions (2015–2025) drawn from every NFL skill player, not
from the current board — using only ranked players would mean learning
exclusively from the ones who already worked out. Validated leave-one-season-out.

Out-of-sample R²: **WR 0.656 · TE 0.649 · RB 0.597 · QB 0.405.**

Each position runs on 6–8 inputs; the card draws the four carrying most of the
weight as bars and rolls the rest into a single "smaller factors" total, so the
contributions on screen sum exactly to the projection. That total is **not**
expandable and the tail is **not** itemised — the line exists to close the
arithmetic, not to list every input.

`team_change` is held out of the headline four regardless of its weight. It is
binary and 85% of the top-150 board stayed put, so it reads as the same nudge on
six cards out of seven. Note it looks fine by any statistic computed on the
training corpus — that corpus is full of fringe players who move constantly, and
its spread there is the widest of any input. The board is not that population.

`FEATURES` in `fit_wide.py` is a **decided set, not a search result.** Each input
survived a drop-one audit and a five-origin rolling validation (fit through year
Y, score everything after it) — a harder test than the leave-one-season-out score
that picks `alpha`. The script asserts nothing fits to zero rather than pruning,
because a set that needs pruning has not been audited.

Removed deliberately, with the reasons, so they do not creep back:

- **`gp`, everywhere.** It was shrinkage in disguise. Prior PPG measured over
  8–11 games predicts next season at 0.67; over a full season, 0.85. A small
  positive weight on games played was the only way a linear fit could say "trust
  this input less". Removing it costs nothing. It is *not* a health signal —
  17-game players average **lower** next-year PPG than 15–16 game players at
  every position, because that group skews to durable low-usage roles.
- **`target_share` at WR and RB, `td_oe_pg` at TE** — each measurably hurt.
- **Career-best PPG and gap-below-peak at QB.** +0.032 on one hold-out, then a
  loss on the largest rolling origin and a bigger "gain" the smaller the test set
  got. That is the shape of noise; n=281 does not support them.
- **Anything derived from the season being predicted.** Incoming-quarterback
  quality looked like the find of the audit (WR +0.010) and was reading next
  year's stat line. Restricted to what is knowable in August it is +0.0015.

`draftScore.test.js` asserts the removed inputs stay out.

**The card's four are ranked by fitted weight, never hand-kept.** A hand-kept
list drifted out of date and put a zero-weight driver on the RB card and QB's
eighth-largest input on the QB card. `draftScore.test.js` asserts both that no
input is dead and that `headline` really is the top four.

### Games, totals and injuries

The card leads with a **season total**, and positional rank / VORP / the ADP score
are all built from it rather than from points per game. A back who scores 15 a
game across nine games is not the RB5 his rate implies.

Total = points per game × projected games, both computed from the **rounded**
parts so the card's arithmetic closes for a reader who multiplies them.

**Projected games is deliberately thin.** Availability barely repeats: prior games
played correlate 0.10–0.23 with the next season's, and a fit on games, durability
and age explains 1.7% of the variance at RB and 9% at QB, residual ~3 games at
every position. `GAMES_MODEL` is therefore a positional baseline plus a career
durability term and nothing else. Do not spend effort making it cleverer.

**Injuries cost the weeks `returnDate` rules out, plus a severity premium.**
Weeks whose first game kicks off before the player is cleared come off the
schedule (`SEASON.weeks` carries the real calendar, so nothing guesses at dates),
and the remaining share scales the healthy baseline — scaling rather than
subtracting, because the baseline already prices in the ordinary missed game.

The premium exists because **a published return date is a floor, not an
expectation**: ESPN reports the next re-evaluation. Jeanty left practice unable to
put weight on a knee and the feed gave a date four days later, which on dates
alone cost him nothing. `DESIGNATION_RISK` × `BODY_PART_SEVERITY` in
`draftScore.js` add the expected miss beyond the date. **Both tables are priors,
not fits** — the feed only ever holds today's report, so there is no history of
what players carrying a designation actually went on to miss. They live in one
place so the judgement is visible and tunable.

**Career durability is shrunk toward the positional mean** by two seasons' worth
of prior, so a rookie who played 17 games does not read as a 1.000 iron man on a
sample of one. The fitted weight is ambiguous (WR prefers none, TE prefers a lot,
the spread is inside the noise), so the constant is a modest uniform prior.

Worth knowing before trying to make this more individual: it already is, and the
spread is genuinely small. Next-season games by career durability band at RB runs
13.0 (below 0.60) to 15.6 (above 0.96) — the whole range is 2.5 games, and a
linear fit tracks those bins to within 0.3. Recent-seasons durability predicts no
better than career.

Rookies have no stat line and are graded off **the mean of their draft band and
nothing else** — no fitted curve. The band means are recency-weighted with a
five-year half-life, and forced non-increasing so a later pick can never project
above an earlier one. The projection therefore equals the average the card cites
as its evidence, exactly; the range around it is that band's own spread.

### Rules that are easy to break

**Every coefficient is sign-constrained.** Volume and production may only help;
age, touchdowns-over-expected, interceptions and a team change may only hurt.
This is not decoration — an unconstrained fit scores marginally higher and hands
back collinearity artifacts that cannot be shown to a user (it wants snap share
as a *negative* driver and touchdown luck as a *positive* one). `fit_wide.py`
asserts the signs and fails loudly rather than shipping a bad fit.

**Draft capital is excluded for veterans.** It measures up as a lever but is
pedigree standing in for performance — a back with three seasons on tape was
getting +1.2 PPG from his draft slot. It remains the whole basis of the rookie
model, where there is nothing else.

**The blend is anchored on the prior season, not the player's own last one.**
`blendedFeature` walks back from `MODEL_SEASONS[1]`. Anchoring on `seasons[0]`
meant a player who sat out all of last year had the year before treated as
yesterday: Joe Mixon missed 2025 entirely and projected off 2024 at full recency
weight, landing at RB13 with a value-vs-ADP of 100 while unsigned.

A window slot the player was in the league for and has no season in pulls the
standardised input toward the league average by that slot's weight. A slot he
*predates* does not — a second-year player is not absent from the season before
he was drafted. Thin seasons count proportionally: a season counts as
`gp / GAMES_MODEL[pos].mean` of a data point, capped at one, so a one-game cameo
is not read as a year of evidence. The reference is the corpus average (~13.6),
not 17, or every healthy player would look partly absent.

**Free agents get no projection at all.** A stat line describes a job they no
longer have, and `canonicalTeam` returns undefined for `FA`, so the team-change
penalty was silently falling back to the league median — the most uncertain case
on the board was getting the average treatment.

**Rank is computed over the whole board, so the visible list has gaps.** The page
shows the top 150 by ECR while ranks run over every scored player, so a player the
model rates highly and the market does not leaves a hole (RB11 → RB13). That is
the model disagreeing with consensus, not a bug — do not "fix" it by ranking
within the slice, which would break VORP.

**Projections are built from the full board, then sliced.** Value over
replacement and the ADP score are relative measures; computing them off the
visible top 100 puts replacement level inside the starters and inflates
every VORP.

**Team abbreviations differ between sources.** nflverse writes the Rams `LA`, the
board writes `LAR`. `draftScore.js` aliases them — without that, every Rams
player reads as having changed teams and is wrongly marked down.

**The kit is half-PPR only**, whatever format the rest of the board is set to.
That is stated on the page rather than assumed; don't quietly make it look
format-aware.

### Levers already tested and rejected

Don't re-add these without new evidence — each was measured and failed:

- **Strength of schedule** — negative at all four positions. The spread between
  the easiest and hardest 2026 schedule is ~2.5 points/game of opponent defence.
- **Team context** (pace, pass rate, offensive EPA, points, sack rate, rushing
  efficiency) — at or below zero everywhere. Collinear with the player's own
  stats, which already encode the offence.
- **Head-coaching change** — WR −0.0005, RB +0.0002, TE +0.0001, QB −0.0047.
  Teams fire coaches after bad seasons and that badness is already in the
  player's line.
- **Orthogonalising the collinear tail** — residualising each opportunity metric
  against the position's production block, so it carries only what prior PPG does
  not already explain. The obvious fix for six-of-thirteen inputs fitting to
  zero, and it does nothing: WR +0.0009, RB +0.0003, TE +0.0001, QB +0.0026, all
  at or under the noise floor, and WR ended with *fewer* live inputs than before.
  The tail is genuinely redundant, not badly fitted. See `test_resid.py`.
- **Rookie levers beyond the band mean** — landing spot (vacated prior-year
  positional opportunity) is real for RB, +0.035 R² over draft capital with
  monotone terciles (6.6 → 8.7 → 10.9 PPG, n=215), and positional rank within the
  class adds +0.026. Both were declined deliberately: the rookie branch is kept to
  the band mean alone. Age at draft measured as nothing (+0.001).

**The rookie era trend is real, but only for pass catchers.** Do not repeat the
mistake of quoting the RB number for all four positions — the year coefficient on
every drafted player is WR +0.098 PPG/yr (t = +1.91), TE +0.100 (t = +2.06),
QB +0.208 (t = +1.41), RB −0.019 (t = −0.26). RB is the one genuine null. Pooling
seasons flat had every top-12 WR projected at 7.72, an average dragged down by a
five-player 2015–19 cohort containing Kevin White (0.00 PPG, never played) and
John Ross (−0.60, three games), against 9.42 for the thirteen taken since 2020.
Recency weighting is what fixes that; it is a prior about relevance, not a claim
that each position's trend is individually significant.

Measured, marginal, not shipped:

- **Splitting the QB fit into passing and rushing** — the two blocks correlate
  only ~0.4 and decompose cleanly (r = 0.995), and fitting them apart scores
  +0.0044. Real but thin on n=281, and it doubles the QB model for about 1%
  relative. See `test_qbsplit.py` if you want to revisit it.

Untestable with current feeds: **coordinator changes** (no nflverse feed carries
OC history) and **depth-chart rank** (`depth_charts` only goes back to 2024 — two
transition pairs).

## Draft Grader

`/draft-grader` — beta, same `beta: true` flag on its route. Takes a roster
(manual search or a Sleeper league id) and reports expected points per week
against what an average team in the same league scores.

- `src/utils/draftGrader.js` — availability, lineup optimiser, league average,
  grade. `src/components/DraftGrader.jsx` — the page. Lazy-loaded in `App.jsx`
  and **must stay that way**: it runs on the Draft Kit's projections, so it pulls
  `playerStats.js` with it.
- **The league average is the top `slots × teams` at each position.** The
  starters at a position across a whole league are near enough its top N, so
  averaging that group gives what an average manager gets from that slot. Flex is
  the best remaining flex-eligible players after the dedicated slots.
- **Lineups are set a week at a time.** Byes come from `SEASON.byes` (derived in
  `fit_wide.py` — a team's bye is the week it has no game) and injuries from the
  return date. This is the whole point: a roster can grade A- on the season and
  still have both starting backs on bye in week 6, which is invisible in a
  season-average number.
- **A slot with nobody eligible is streamed, not zeroed.** Nobody leaves a lineup
  spot empty on a bye; they take whoever is on waivers. The streamer is worth the
  average of the `teams` players starting at `REPLACEMENT_RANK` for that position,
  scaled to league size — this codebase already defines that rank as the waiver
  line. Scoring an empty slot as zero made a bye look like a catastrophe instead
  of the mild tax it is.
- Greedy filling is optimal because slot types are nested — every flex-eligible
  player is also eligible for his own position's slot — so filling dedicated
  slots first never strands a better flex option.
- Half-PPR only, like the Draft Kit, and stated on the page.

### Matchups

Each weekly score moves by up to **±`MATCHUP_SWING`** (3 points) for that week's
opponent. `SEASON.schedule` carries who plays whom, derived in `fit_wide.py`.

**The ranking is the board's own 2026 team-defence ECR, not last season's points
allowed.** That matters twice over. Historical points-allowed describes a roster
that has since changed, and it barely predicts itself anyway — a defence's rating
correlates with its own next season at **WR +0.08** (negative in two of the last
four transitions), QB +0.12, TE +0.19, RB +0.30. The board's DST ranks are a
consensus view of how good each unit will be *this* year, and they update
whenever the board does, so nothing needs regenerating.

Rank *position* is mapped linearly onto ±3 rather than the raw ECR, because the
consensus gaps are uneven (173, 177, 180 … then a jump to 284) and raw numbers
would bunch most teams near zero. Teams with no ranked defence are neutral.

The swing is held tight on purpose given how thin the underlying signal is: it
reorders close calls rather than deciding them. It does genuinely change lineups
— a +2.8 draw can promote a 12.0 back over a 9.4 receiver in the flex — but over
18 weeks a team faces good and bad defences, so the season grade barely moves.
That is the season-long strength-of-schedule rejection showing up again, and it
is why the adjustment belongs in the weekly view rather than in the projection.

## Front-end conventions

- Dark mode is a `darkMode` boolean threaded down as a prop, persisted via
  `useLocalStorage('dark-mode')`. There is no theme context.
- Styling helpers live in `src/utils/uiTheme.js` (`ui.card(dark)`, `ui.btn(dark)`,
  `ui.modal(dark)`, `ui.statPill(dark, tone)`…). Use them instead of hand-rolling
  Tailwind combinations, so pages stay visually consistent.
- Position badge colors are user-editable — always go through
  `getPositionTagProps` and `usePositionColors`, never fixed Tailwind color
  classes.
- Nav entries are declared in `src/utils/routes.js`; each `icon` key needs a
  matching SVG in `Navbar.jsx` or it renders nothing.
- Tests sit beside their subject as `*.test.js(x)`. `src/server-tests/` covers the
  `/api` handlers.
